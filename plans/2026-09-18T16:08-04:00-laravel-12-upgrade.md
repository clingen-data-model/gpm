# Upgrade to Laravel 12

## Context

The repo is currently on `laravel/framework ^11.0` (locked at v11.47.0), on branch `composer-updates-202609`, which is already mid-way through a broader dependency-upgrade effort (recent commits bumped dompdf to 3.0 and temporarily disabled `composer.json`'s `audit.block-insecure` check while upgrading things). The goal is to move to Laravel 12 as the next step in that effort.

Per the [official Laravel 12 upgrade guide](https://laravel.com/docs/12.x/upgrade), this is a small release — Laravel itself estimates "5 minutes," with mostly Low/Very-Low impact changes and only two High-impact items (bump `laravel/framework`, bump `phpunit`/`pest`). A full audit of this codebase against every item in the guide found it is exceptionally well-positioned for the bump:

- **PHP**: the app's container image (`ghcr.io/clingen-data-model/cgwi-php-13.2-8.5:v1.1.11`, see `docker-compose.yml`) already runs PHP 8.5 — above Laravel 12's `^8.2` floor. No change needed.
- **Carbon**: already locked at 3.11.0, satisfying Laravel 12's Carbon-3-only requirement.
- **PHPUnit/Paratest**: already required at `^12.5`/`^7.16` (ahead of Laravel 12's own `^11.0` ask), and already satisfy `nunomaduro/collision` v8.8.3's conflict rules (`phpunit <11.5.15`, `laravel/framework <11.44.2`) — no version changes needed there.
- **All other Laravel-ecosystem packages** currently vendored (Fortify, Sanctum, Telescope, laravel-impersonate, slack-notification-channel, laravel-actions, laravel-log-viewer, spatie/activitylog, spatie/permission, spatie/ignition, clockwork) already declare support for `illuminate ^12.0` / `laravel/framework ^12.0` at their currently-locked versions.
- **None of the breaking changes in the guide touch this codebase**: no `Concurrency::run`, no container-resolved nullable-typed constructor properties relying on auto-resolution, no custom `Blueprint`/`Grammar`/`Connection` subclasses or `setConnection()`/`setTablePrefix()` calls, no `DatabaseTokenRepository` customization, no `Request::mergeIfMissing()` dot-notation usage, no duplicate named routes, no `Schema::getTables()`/`getViews()`/`getTypes()`/`getTableListing()` usage. Production DB is MySQL; tests run on SQLite in-memory.
- `config/filesystems.php` explicitly defines the `local` disk root as `storage_path('app')`, so Laravel 12's new *default*-root change doesn't apply (it only kicks in when the disk isn't explicitly configured).
- The `image` validation rule appears only in `FundingSourceCreate`/`FundingSourceUpdate` (funding source logos), already restricted to `mimes:png,jpg,jpeg,gif` — Laravel 12 excluding SVG from the bare `image` rule has zero practical effect here.

**One item requires a conscious decision rather than a code fix**: `app/Modules/Person/Models/Attestation.php` uses `HasUuids` on its primary key. Laravel 12 changes this trait's default from UUIDv4 (random) to UUIDv7 (time-ordered). Nothing in the codebase depends on v4-specific randomness or format, but the user has decided to **preserve the current UUIDv4 behavior** rather than take the new default, to keep this primary key's format unchanged. This requires a one-line swap of the trait import in that file to `HasVersion4Uuids as HasUuids`.

The `audit.block-insecure: false` FIXME predates this effort and is explicitly **out of scope** — do not fold its revert into this work.

## Implementation

### 1. Branch

Continue on the current branch (`composer-updates-202609`) since this is a continuation of the in-flight dependency-upgrade series on that branch, rather than forcing a new `feat/` branch that would duplicate in-progress work.

### 2. Composer changes

In `composer.json`, change only:
```diff
- "laravel/framework": "^11.0",
+ "laravel/framework": "^12.0",
```
Leave `phpunit/phpunit`, `brianium/paratest`, and `nunomaduro/collision` untouched — already compatible, per the audit above.

### 3. Run the update (container conventions per this repo's own README)

```
docker compose up -d db redis
docker compose run --no-deps --rm -it --entrypoint composer app update laravel/framework --with-all-dependencies
```
`--with-all-dependencies` lets composer bump the already-`^12`-compatible `illuminate/*`/`symfony/*` sub-packages as needed, while every other package's own `composer.json` constraint (e.g. `laravel/telescope: ^5.10`) still caps it from an unwanted major bump elsewhere. Treat a solver failure or an unexpected major version shift on any *other* package as a stop-and-reassess signal, not something to push through.

After a clean resolve, check `git diff composer.json composer.lock` to confirm only `laravel/framework` and its direct transitive deps moved — nothing from the recent dompdf/other work shifted unexpectedly.

Optionally run `docker compose run --no-deps --rm -it --entrypoint composer app audit` afterward and note (don't act on) any framework-related findings for whoever eventually handles the `block-insecure` revert.

### 4. Verification

- **Full test suite**: `docker compose run --no-deps --rm -it app bash -c "vendor/bin/phpunit"` — exercises SQLite in-memory DB, Eloquent models (including `Attestation`), the funding-logo `image` validation rule, and routing.
- **Boot sanity check**: `docker compose run --no-deps --rm -it app bash -c "php artisan about"` — confirms the app boots under Laravel 12 and surfaces any config/service-provider incompatibility immediately.
- **Route/config sanity**: `php artisan config:clear && php artisan route:list > /dev/null` inside the container.
- **Attestation UUID check**: a quick `artisan tinker` check creating/inspecting an `Attestation` record's `uuid` to confirm it's still v4-formatted after pinning `HasVersion4Uuids`.
- **Frontend build** (unrelated to the PHP bump but part of normal CI): `npm run build`.

### 5. Commit structure

Per the user's one-concern-per-commit convention, with generated files split from hand edits:

1. `composer.json` constraint bump alone — e.g. "Bump laravel/framework to ^12.0".
2. Resulting `composer.lock` diff — e.g. "Regenerate composer.lock for Laravel 12" (kept separate/droppable).
3. The one-line `Attestation.php` trait-alias change (`HasVersion4Uuids as HasUuids`) to preserve UUIDv4 generation, as its own commit — e.g. "Preserve UUIDv4 generation for Attestation primary key".

Do not bundle the `audit.block-insecure` revert into any of these commits.
